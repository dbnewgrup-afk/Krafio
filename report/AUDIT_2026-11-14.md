## 2. Temuan yang sudah diperbaiki

### A1. Rate limit login bisa ditembus dengan header palsu — **Tinggi** (PRD 10.2)

- **Masalah:** `bootstrap/app.php` memakai `trustProxies(at: '*')`. Akibatnya IP klien diambil dari header `X-Forwarded-For` yang bisa diisi siapa saja. Semua rate limit berbasis IP (login user, login admin, OTP, registrasi, tiket) bisa dilewati hanya dengan mengganti header itu.
- **Bukti:** login admin terkunci setelah 5 kali gagal dari IP yang sama, tapi tetap bisa dicoba terus dengan `X-Forwarded-For: 10.1.1.1`, `10.1.1.2`, dan seterusnya.
- **Solusi:**
  - Middleware baru `app/Http/Middleware/TrustProxies.php` hanya mempercayai proxy yang terdaftar di env `TRUSTED_PROXIES` (`config/krafio.php`). Defaultnya kosong.
  - Kunci kedua per akun: login admin terkunci setelah 10 kali gagal per email dari IP mana pun, login user setelah 4× batas per IP. Turnstile juga aktif setelah 3 kali gagal per akun.
  - Admin yang statusnya ditangguhkan sekarang ditolak di langkah MFA dan di middleware `EnsureAdmin`.
- **Tindakan saat deploy:** kalau aplikasi berada di belakang Cloudflare, isi `TRUSTED_PROXIES` dengan rentang IP Cloudflare (https://www.cloudflare.com/ips/). Kalau nginx memanggil PHP-FPM langsung tanpa CDN, biarkan kosong.

### A2. Klik ganda pada approval mengembalikan dana dua kali — **Sedang** (keuangan, PRD 5.5, 11.4)

- **Masalah:** status approval dicek di luar transaksi dan tanpa row lock. Dua permintaan "Tolak" pada withdrawal yang sama, misalnya karena klik ganda atau dua admin bersamaan, sama-sama lolos dan mengkredit saldo komisi dua kali. `withdrawalStatus` juga tidak mengunci baris.
- **Solusi** (`AdminController::decide`, `withdrawalStatus`):
  - Baris approval dan withdrawal dikunci dengan `lockForUpdate`, lalu statusnya dicek ulang di dalam transaksi.
  - Withdrawal yang sudah diproses tidak bisa diputuskan lagi.
  - Komisi yang ditandai "dibayar" juga dikunci.

### A3. `per_page` negatif memicu error 500 — **Sedang**

- **Bukti:** `GET /api/app/credits/history?per_page=-5` dan `/app/jobs/history?per_page=-1` menghasilkan 500.
- **Solusi:** 13 pemakaian `per_page` sekarang dibatasi minimal 1 (`max(1, …)`).

### A4. Pengaturan keamanan dan uang bisa diubah tanpa konfirmasi kata sandi — **Sedang** (PRD 10.2, 31)

- **Masalah:** `PUT /admin/settings` bisa mematikan MFA admin, mengganti gateway atau webhook secret, mengubah persentase affiliate dan batas refund, atau memendekkan retensi audit log, tanpa re-autentikasi. Padahal penyesuaian saldo sudah wajib re-autentikasi.
- **Solusi:** perubahan kunci `security.*`, `payment.*`, `wallet.*`, `affiliate.*`, `refund.*`, `billing.*`, `credits.*`, `registration.*`, `retention.*`, dan `backup.*` wajib re-autentikasi (15 menit), tapi **hanya kalau nilainya benar-benar berubah**. Frontend (`AdminSettings`, halaman Backup) sudah memakai `withReauth`, jadi admin otomatis diminta kata sandi.

### A5. Lampiran inbox menerima URL apa pun — **Sedang**

- **Masalah:** user bisa mengirim `attachments[].url` berisi URL eksternal. Gambar itu lalu dimuat di panel admin, sehingga bisa dipakai untuk melacak IP admin atau menampilkan konten phishing. XSS lewat `javascript:` sudah tertahan oleh React 19.
- **Solusi:** URL lampiran wajib berformat media Krafio `/api/media/{id}/{nama}` (`InboxController`, sisi user dan admin).

### A6. Kunci idempotensi bersifat global — **Sedang**

- **Masalah:** kolom `idempotency_key` unik untuk seluruh tabel.
  - Lookup withdrawal tidak memfilter user, sehingga key yang sama bisa mengembalikan data withdrawal milik user lain.
  - Key yang sama dari dua user berbeda, atau key lebih dari 80 karakter, memicu error 500.
- **Solusi:** `app/Support/Idempotency.php` menyimpan `sha256(user_id|key)`. Dipakai di order, top-up, withdrawal, dan job AI.

### A7. CORS mengizinkan semua origin — **Rendah**

- **Solusi:** `config/cors.php` hanya mengizinkan `FRONTEND_URL`.

### A8. `robots.txt` dan `sitemap.xml` tidak ada — **Sedang** (SEO situs publik)

- **Masalah:** kedua URL mengembalikan halaman HTML SPA. `og:image` memakai path relatif, sehingga pratinjau tautan di WhatsApp dan Facebook gagal.
- **Solusi:**
  - `apps/frontend/public/robots.txt` menutup `/app`, `/admin`, dan `/api`.
  - `sitemap.xml` berisi 29 URL publik, termasuk 11 halaman fitur.
  - `og:image` sekarang memakai URL absolut.
  - Domain yang dipakai `https://krafio.id`. Sesuaikan kalau domain produksinya berbeda.

### A9. Kebersihan test

- Menjalankan test menimpa `storage/app/private/admin-credentials.txt` dengan password dari database test, sehingga password admin lokal di file itu jadi salah. Seeder sekarang tidak menulis file tersebut saat `APP_ENV=testing`.
- `php artisan test` tanpa argumen gagal karena folder `tests/Unit` tidak ada. Folder itu sekarang sudah ada, berisi test sanity konfigurasi proxy.

## 4. Yang sudah baik

- Ledger uang dan kredit append-only, dengan `lockForUpdate` per user. Saldo top-up dan komisi terpisah, dan ini sesuai uji PRD 17.3.
- Pengecekan kepemilikan (anti-IDOR) konsisten di semua controller user: proyek, job, file, website, tiket, pembayaran, dan tujuan pencairan.
- Webhook pembayaran memverifikasi HMAC, nominal, dan referensi, serta idempoten. Pembayaran yang masuk setelah tagihan batal diteruskan ke admin, tidak diaktifkan diam-diam.
- Upload divalidasi MIME di server, disimpan privat, dan dibatasi kuota storage per paket. Media publik memakai nama acak 40 karakter.
- CSV ekspor terlindung dari formula injection.
- Error API memakai format standar tanpa stack trace.
- Admin memakai MFA TOTP, timeout sesi idle, dan re-autentikasi untuk keputusan keuangan.
